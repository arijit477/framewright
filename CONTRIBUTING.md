# Contributing to Framewright

Thanks for helping. This guide covers setup, conventions and the PR process.

## Setup

Follow **Getting started** in the [README](README.md). If `pnpm dev` runs and you can import a
video, you're set.

## Where things live

Read [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) first. In short:

- **Editing rules** (what's a valid timeline) belong in `crates/engine`, with a Rust test.
- **Decoding and drawing** belong in `apps/web/src/render`.
- **Timeline interaction** belongs in `apps/web/src/timeline`. Keep maths in `geometry.ts`,
  which is pure and tested.
- **App state and commands** belong in `apps/web/src/store/editor.ts`. Every timeline change
  goes through `edit()`, so it gets validation and undo for free.

## Workflow

1. Open an issue (or comment on one) before large changes, so we can agree on the approach.
2. Branch from `main`: `feat/short-description`, `fix/...`, `docs/...`.
3. Make your change with tests.
4. Run the checks locally:

   ```bash
   pnpm format && pnpm lint && pnpm typecheck && pnpm test
   pnpm build && pnpm test:e2e   # for UI, media or export changes
   ```

5. Open a PR using the template. CI must pass.

## Testing

Each layer is tested where it's cheapest to test thoroughly:

| Layer         | Tool                                  | What belongs there                                                                                                                                        |
| ------------- | ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Engine rules  | `cargo test`                          | Every timeline invariant: overlaps, trims, splits, volume bounds, JSON compatibility.                                                                     |
| Pure TS logic | Vitest (`*.test.ts` next to the code) | Maths and protocols: mixer timing, resampler, ring buffer, geometry, export settings. Inject fakes instead of real media (see `audio/mixer.test.ts`).     |
| Whole app     | Playwright (`apps/web/e2e`)           | User flows against the **production build**. Exports are checked independently with ffprobe/ffmpeg: codecs, exact frame count, clean decode, audio level. |

Run the browser tests locally (needs ffmpeg on your PATH):

```bash
pnpm build && pnpm test:e2e
```

Rules of thumb:

- A bug fix comes with a test that fails without the fix.
- New UI flows get an e2e test. Interact through `e2e/editor-page.ts` (page object) so layout
  changes only touch one file.
- Test media is generated by `e2e/global-setup.ts`; don't commit binary fixtures.

## Conventions

- **Commits** follow [Conventional Commits](https://www.conventionalcommits.org/):
  `feat(timeline): snap to playhead`, `fix(render): close frames after submit`.
- **Times** are integer microseconds everywhere ([ADR 0001](docs/adr/0001-time-in-microseconds.md)).
- **No main-thread decoding or encoding.** Media work goes in a worker.
- **Close every `VideoFrame`/`VideoSample`** you create, or decoders stall and GPU memory leaks.
- **Dependencies:** check the licence (no GPL) and add a row to
  [docs/DEPENDENCIES.md](docs/DEPENDENCIES.md) in the same PR.
- **Significant design decisions** get an ADR in `docs/adr` (copy `0000-template.md`).

## Reporting bugs

Use the bug report template, and include your browser and version, OS, GPU, and the shown
backend (top-right: "WebGPU" or "Canvas 2D"). If possible, attach a short clip that
reproduces the problem.
