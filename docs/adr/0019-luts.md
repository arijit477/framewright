# 0019: LUTs (3D colour look-up tables)

- **Status:** Accepted
- **Date:** 2026-11-04

## Context

Colourists and creators share looks as LUTs, mostly as `.cube` files (Adobe and DaVinci Resolve
format). A LUT is data the user brings in, so unlike the colour sliders (ADR 0015) it has to be
stored with the project, travel in backups, and reach both render workers. And as with every
effect, the preview (WebGPU or Canvas 2D) and the export (Canvas 2D) must match.

## Decision

- **Parsing (`render/lut.ts`):** 3D `.cube` files, sizes 2–65, default 0–1 input range. Outputs
  are clamped to 0–1. 1D LUTs and custom input ranges are refused with a clear message.
- **Storage:** LUTs live in the **project document** (format version 2, migrated from 1 by
  adding `luts: []`), not in the engine timeline. The timeline is snapshotted for every undo step
  and a LUT is ~290 KB, so keeping LUTs out of it keeps editing fast.
  - Entries are stored as 16-bit integers, base64, and rendering always uses exactly what was
    stored.
  - Because they're in the document, saves and `.framewright` backups include them with no
    extra plumbing.
  - Projects are validated on load (size, data length, unique ids). A damaged LUT is left out
    with a notice.
- **Clips** refer to a LUT by id with an intensity (`LutRef { lutId, intensityPercent }` in the
  engine). It is kept on split and paste, and is part of undo. A clip whose LUT is missing renders
  without it.
- **The LUT applies before the colour sliders**, so they fine-tune a look.
- **Maths:** trilinear interpolation between the 8 surrounding entries, blended with the original
  by intensity. `applyLutRgb` is the tested reference.
  - **WebGPU** uses a 3D `rgba16float` texture: the hardware's linear filter is exactly
    trilinear, sampling entry centres. Layers without a LUT bind a 2³ identity at intensity 0.
  - **Canvas 2D** (and so export) runs `lutPixels`, which has the grid positions for all 256
    byte values precomputed. It works at the frame's size, capped at the output canvas.
  - The WebGPU self-test draws red through an inverting LUT and desaturates it. Only cyan's grey
    passes, which checks the lookup, the order and the colour maths. A mismatch falls back to
    Canvas 2D.

## Consequences

- Old projects open unchanged (migrated). A project saved with LUTs needs this version or newer
  to open; older apps refuse it with "saved by a newer version".
- Each LUT adds to every save (a few hundred KB), so unused ones can be removed (see the addendum
  below).
- Canvas 2D cost: about +40 ms per 1080p frame in the GPU-less CI sandbox. A 6 s clip with a
  LUT exported at 1080p in 10.7 s there. WebGPU previews do the lookup on the GPU.
- Not yet: tetrahedral interpolation, custom input ranges (log footage), 1D LUTs, keyframed
  intensity, and LUTs on titles.

## Alternatives considered

- **LUTs in the timeline JSON:** simplest, but every edit would copy them into the undo history.
- **LUTs as media files in project storage:** scales to many large LUTs, but needs its own
  storage, backup and relink handling. It may be worth it if projects collect many LUTs.
- **8-bit storage / textures:** half the size, but visible banding in smooth gradients.

## Addendum: managing project LUTs

- A **Manage LUTs** dialog (from the Color section) lists the project's LUTs with their size and
  how many clips use each. Names can be changed (tidied, never empty). Unused LUTs can be
  removed one by one or all at once ("Remove unused"). The total stored size is shown.
- **A LUT in use can't be removed:** the button is disabled and says why. This keeps saved
  projects free of references to missing LUTs.
- **Undo safety:** removing isn't an undo step, but a removed LUT is kept in memory for the
  session. If undo, redo or a paste brings back a clip that uses it, it's restored to the project
  automatically (checked after every timeline change). Undo history doesn't survive a reload, so
  nothing saved can refer to a removed LUT.
- **The clipboard carries LUTs:** copied clips bring the LUTs they use, and a paste adds any the
  project lacks. A clip copied before its LUT was removed (even across opening another project)
  is still graded when pasted.
